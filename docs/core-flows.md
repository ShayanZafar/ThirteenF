# Core flows

This file lists what a person relies on ThirteenF for and names, for each flow, the tests at each level the [definition of done](../CLAUDE.md#definition-of-done) asks for: unit (one module, no network), integration (real routes, DuckDB or the ingest pipeline together, outside services played by stand-ins) and UI (a real browser driving the running app), with `—` for a gap. `scripts/verify.sh` checks it with `scripts/check_core_flows.py`, failing when a flow lacks a level, a named test no longer exists, or the gaps differ from the count below, which only ever goes down. All three levels run on every pull request: tests that need the real SEC download or another live service (the `data` tests) are kept separate and are not named here. The UI tests (marked `ui`) drive headless Chromium through Playwright against the app served by `uvicorn` in the test process (the `app_url`, `browser` and `page` fixtures in `tests/conftest.py`), on the made-up data set with OpenFIGI and the SEC played by stand-ins.

The one gap: being told that a data source stopped answering happens on the command line (`update-data` and `python -m thirteenf.tickers` end with a "Sources:" line), and no page shows it, so a browser has nothing to check. Closing it needs the pages to show the warning, which is the owner's decision ([#25](https://github.com/ShayanZafar/thirteenf/issues/25)).
